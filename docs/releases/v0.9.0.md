# v0.9.0 - Vector 多行边界修正与采集端资源经验

本版本沉淀测试与生产 Kubernetes 采集端、主机 Compose 采集端一轮现场排查的结论。
完整背景、数值和操作要求见
[内存与恢复手册](../vector-memory-and-recovery-runbook.md#2026-11-现场复盘多行边界追赶内存与配置漂移)。

## 变更

- VVG 多行合并 `starts_when` 增加 IPv4 行首规则。Nginx/combined 访问日志每行单独成为
  一条记录，不再在连续流量下合并成几十万行的超大记录；现场 collector 内存约减半。
- 继续保持“正常多行日志不按固定行数拆段”的基线：网关合法多行日志实测最大约 1.7 万行，
  不引入 `max_events`。多行回归测试新增访问日志保持逐行的断言。
- 直写 VVG 模板的 readiness/liveness 探针超时由默认 1 秒改为 5 秒、失败阈值 5 次；
  memory request 调整为 512 MiB（containerd）/ 384 MiB（docker），接近实测稳态。
- Gateway 采集端内存上限由 1 GiB 调整为 1.5 GiB（GeoIP 库常驻内存）。
- AutoMQ 生产示例清单由生成器重新渲染，`vector-config-sha256` 随配置更新。
- 主机 Compose 采集端与通用 Docker 采集端的内存上限改为 `VECTOR_MEM_LIMIT`（默认 `1g`），
  通用 Docker 采集端补齐原来缺失的 CPU/内存上限；按 source 数量与重启追赶峰值设置。
- `validate-configs.sh` 增加 IPv4 行首规则和内存参数化的静态检查。

## 运维经验

- 修改现场清单前导出线上对象并 `kubectl diff`；文件落后于线上时先按线上重建。
- 只改 ConfigMap 时用 `vector-config-sha256` 注解触发滚动，不制造文件与线上漂移。
- `docker update` 救急调大资源后，必须在同一次变更中同步 Compose，否则重建后复发 OOM。
- 统计采集端内存时区分 cgroup 匿名内存与文件缓存。

## 升级与回滚

现场清单仍以目标环境当前源文件为准，不用仓库公开示例覆盖解析、GeoIP、checkpoint 或
Secret。按手册导出、diff、`vector validate`、server dry-run 后再滚动；回滚使用变更前导出的
源文件。已有 Compose 部署设置 `VECTOR_MEM_LIMIT` 前先测量稳态内存。

## 验证范围

- `scripts/test-vvg-multiline-preservation.sh`：Vector 0.58.0 实测 9000 行 Java 正文逐字节
  合并为一条、3 行访问日志保持 3 条。
- `scripts/render-automq-example-manifests.py --check`、静态与运行时配置校验、单元测试。
- 现场：测试与生产采集端按上述规则滚动后 0 错误、0 告警，按事件时间统计无缺口。
